DomeGallery supplies the cylindrical logo showcase that follows HeroSection. The file starts with 'use client', importing Image plus the @use-gesture/react hook. Type aliases describe image inputs: `type ImageItem = string | { src: string; alt?: string };`. This choice lets calling components pass simple paths plus richer metadata while keeping TypeScript strict. The prop object `type DomeGalleryProps = { images?: ImageItem[]; fit?: number; fitBasis?: 'auto' | 'min' | 'max' | 'width' | 'height'; ... }` spans seventeen tunable fields, covering radius, overlay color, drag behavior, tile geometry, grayscale flag, plus auto-rotate speed. Every field carries defaults, giving downstream sections a reliable visual baseline even when they skip explicit props.

Default images live in a constant array referencing `/assets/website client logos png/*.png`. Embedding those paths locally prevents flaky hotspots that might accompany remote CDNs while also easing future art swaps within the repo. `DEFAULTS` collects baseline motion settings: `maxVerticalRotationDeg: 5`, `dragSensitivity: 20`, `enlargeTransitionMs: 300`, `segments: 35`, `autoRotateSpeed: 0.005`. These values deliver a gentle parallax rather than a dizzying spin while still feeling responsive whenever visitors drag, even during vigorous flings. Designers can tweak each constant for new campaigns without touching the heavy logic further below.

Utility helpers near the top support future calculations. `clamp`, `normalizeAngle`, plus `wrapAngleSigned` keep rotations within manageable ranges, shielding the page from overflowed matrices. `getDataNumber` fetches numeric dataset values, falling back to defaults if parsing fails, which protects the component from NaNs even if tiles receive unexpected attributes during future refactors. Each helper remains pure, simplifying potential extraction into shared utilities within `lib/` should Bold Frame Media decide to consolidate math later.

`buildItems` constructs positions across the cylindrical wall. Columns extend from -37 to positive coordinates in increments of two, alternating between `evenYs = [-4, -2, 0, 2, 4]` plus `oddYs = [-3, -1, 1, 3, 5]`. This staggering prevents visual seams across the vertical axis while distributing logos with a subtle checkerboard rhythm. The function normalizes every ImageItem into `{ src, alt }`, then cycles through that list to populate available slots, swapping identical neighbors to avoid immediate repetition. The final array stores x, y, plus tile size information for later transforms, enabling subsequent layers to remain stateless regarding layout math.

`computeItemBaseRotation` translates tile offsets into rotation values relative to the cylindrical surface. Each tile sits on a curved wall, meaning it must rotate around both X plus Y axes to face the viewer. The helper calculates a base rotation using the segment count, ensuring consistent angles regardless of how many columns the gallery renders. Because the math lives outside the component body, updates remain predictable, while memoization further down ensures those numbers only recalc when props actually shift.

Inside the React component, numerous refs capture DOM nodes plus stateful data. `rootRef`, `mainRef`, `sphereRef`, `frameRef`, `viewerRef`, plus `scrimRef` reference key containers. Additional refs track interactive state: `focusedElRef`, `rotationRef`, `startRotRef`, `startPosRef`, `draggingRef`, `inertiaRAF`, `pointerTypeRef`, `openingRef`, plus caches for scroll locking. This separation keeps imperative DOM manipulations organized, lowering cognitive load while reading the enlargement flow. Anyone triaging a bug can trace responsibilities quickly because data that travels across hooks remains corralled inside refs named after their purpose.

`useMemo(() => buildItems(images, segments), [images, segments])` keeps the generated tile map stable unless props change. That ensures re-renders triggered by unrelated state updates never rebuild the grid, preserving performance even during frequent pointer events. The memoized array feeds directly into child rendering later in the file, which yields deterministic layout without invoking `useState` alongside repeated loops within JSX.

A critical `useEffect` wires a ResizeObserver on `rootRef`. Inside, width plus height determine radii. The logic picks a basis dimension according to `fitBasis`: width, height, min, max, else auto heuristics that inspect whichever axis feels most constrained. The allowed radius gets clamped between `minRadius` plus `maxRadius`. CSS variables `--radius`, `--viewer-pad`, `--overlay-blur-color`, `--tile-radius`, `--enlarge-radius`, plus `--image-filter` update accordingly, letting CSS handle actual layout while JavaScript simply pushes numbers. When an enlarged overlay exists, the observer recomputes its position to stay centered despite viewport shifts.

Inertia receives its own memoized callback. `startInertia` clamps velocity, multiplies by friction, stops when magnitudes fall below thresholds, plus updates `rotationRef`. The loop uses requestAnimationFrame, storing the handle inside `inertiaRAF`. `stopInertia` cancels any pending loop to prevent overlapping animations. Parameters like `dragDampening` influence deceleration curves, giving designers control over how quickly the gallery settles after a fling gesture while still keeping input feel consistent between mouse, pen, plus touch devices.

`useGesture` from @use-gesture/react handles pointer events on `mainRef`. `onDragStart` records pointer type, locks scroll for touch interactions, clears inertia, tracks the starting position, plus notes the potential tile the visitor tapped. `onDrag` calculates deltas, updates rotation via clamp-limited math, determines whether the action qualifies as a tap, then triggers inertia when momentum persists, otherwise opens a tile overlay. Touch interactions release scroll lock once the drag completes, preventing the page from freezing while still blocking stray body scroll during the gesture.

The enlargement workflow represents the most intricate sequence. When a tile gets tapped without significant movement, `openItemFromElement` runs. It computes rotational deltas to reorient the tile toward the camera, clones metadata, captures the tile's bounding box, hides the original image, then creates an overlay element appended to `viewerRef`. CSS transitions animate the overlay into place, optionally resizing to `openedImageWidth` plus `openedImageHeight`. A scrim listens for clicks plus Escape to reverse the process. During closure, a temporary overlay animates back to the tile's original location, after which scroll locks release plus original elements regain visibility. Helper functions `lockScroll` plus `unlockScroll` manage the `dg-scroll-lock` class on `<body>`, ensuring that immersive focus never traps the visitor permanently.

Rendering wraps all of this logic inside a `<section id="dome-gallery" className="relative isolate overflow-hidden ...">`. Inner divs apply overlays, gradient scrims, plus blur effects, while the actual tiles map over `items`. Each tile uses dataset attributes for offsets plus sizes, enabling CSS transforms to position them around the sphere via `transform-style: preserve-3d`. Buttons never appear in markup while overlays stay dynamic because interactivity happens through pointer captures plus dynamically created elements. This approach keeps the static HTML lean while still enabling elaborate interactions through imperative portals that mount only when needed.

DomeGallery accepts numerous props yet remains flexible thanks to its default values. Teams can swap imagery by passing a new array, adjust cylinder radius via `fit`, lock grayscale for brand guidelines, change drag sensitivity without editing internal math, tweak blur colors, plus dial in overlay timings. The component balances CSS-driven presentation with imperative overlays, giving Bold Frame Media a dramatic rotating showcase that still honors performance budgets. Its disciplined structure makes future enhancements—like video tiles, analytics events, plus context-aware theming—straightforward despite the apparent complexity because every hook isolates a single responsibility.
