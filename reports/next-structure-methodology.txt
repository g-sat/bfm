Structure plus methodology form the twin pillars guiding Bold Frame Media's immersive Next.js deployment. The repository divides responsibilities into discrete layers that map directly to user perception: a RootLayout establishes typography plus persistent audio, the Home route orchestrates hero visuals plus narrative sections, while specialized components within `components/Hero`, `components/Overalls`, `components/Works`, plus allied directories deliver motion-infused interactions. This deliberate separation mirrors studio workflows where creative leads iterate on scenes without disturbing infrastructure code. Every module signals its runtime constraints through "use client" directives alongside server defaults, ensuring contributors know upfront whether browser APIs remain available.

At the highest tier, `app/layout.tsx` anchors the document shell. The file imports Geist Sans plus Geist Mono through Next/font, reserving CSS variables that trickle throughout the tree. Metadata declarations define the Bold Frame Media icon plus descriptive tagline, reinforcing brand cues for crawlers. Inside the layout function, markup renders `<html lang="en">` plus `<body>` with font variables plus `antialiased` class, then injects route children followed by the global AudioPlayer. This ordering ensures the soundtrack persists across navigation while page-level sections mount then unmount independently. The layout never reaches for DOM APIs, keeping the server-rendered payload pure while deferring to client components for interactivity.

`app/page.tsx` composes the visible narrative. Comments at the top describe each import, reflecting a methodology that favors clarity for onboarding designers. The `Home` function returns a `<main>` element with relative positioning plus full viewport height, tinted via `bg-[#05030F]` plus white typography. The Navbar sits first to guarantee stable stacking context for scroll interactions. A `div` with `min-h-screen` wraps the hero plus follow-up sections, creating a single flow. HeroSection occupies the upper viewport, followed by DomeGallery inside its own relative container to preserve gradient layers. Sections receive IDs (`about`, `work`, `contact`) to support hash-based navigation plus IntersectionObserver logic inside the Navbar. The route concludes with FooterSection. Every component import lives under the `@/components` alias, keeping references short plus resilient to structural tweaks.

The hero stack exemplifies the application methodology: luminous backgrounds, WebGL sculpture, kinetic typography, plus interactive frames collaborate inside a single viewport without conflicting event zones. `HeroSection` resides in `components/Hero/HeroSection.tsx` with a "use client" directive, acknowledging the need for GSAP, pointer listeners, plus Three.js hooks. The component returns a `<section>` containing layered radial gradients built with Tailwind's arbitrary values. Several absolutely positioned `div`s deposit blurred colors to simulate volumetric fog. Another `div` hosts `ProximityHeroFrames`, a mosaic that slides imagery based on pointer proximity, though its implementation sits outside this excerpt. This background scaffolding illustrates the team's approach: expensive visuals remain purely CSS when feasible, preserving runtime budgets for heavier modules like `Hero3D`.

Inside the hero layout, a flex container centers content while preserving `min-h-screen`. `Hero3D` demonstrates the pattern for advanced browser experiences. The component imports `Canvas` from `@react-three/fiber`, the `Model` definition, plus utilities from Three.js. A `useRef` holds the underlying `Group`. Within `useEffect`, the code sets an initial rotation by converting degrees to radians through `MathUtils.degToRad`. Mouse movement listeners compute normalized coordinates relative to the viewport before lerping rotation via `MathUtils.lerp`. The Canvas sets `gl={{ alpha: true }}` plus `style={{ background: "transparent" }}` to avoid interfering with CSS gradients beneath. Ambient plus directional lights establish depth, while the `Model` scales to `0.8` plus centers at the origin. Because the component never directly references document-level styling, it remains portable to future scenes, supporting the team's methodology of isolating input handling from rendering definitions.

Parallel to the 3D sculpture, `HeroText` turns typography into a cinematic sequence. A `useRef` targets the `<h1>`. During `useEffect`, the script splits the phrase "BOLD FRAME" plus "Media" into spans, injecting them into the heading. A CTA button below leverages `useRef` plus pointer tracking to drive a gradient blob that follows the cursor. This micro-interaction reinforces methodology: intangible delight emerges from precise pointer math plus measured animation timing, while textual structure stays accessible because final HTML still contains semantic `<h1>` tags with spans rather than canvas text.

`components/Overalls/Navbar.tsx` houses the navigation brain. The component imports React hooks, Next.js navigation utilities, Next/Image, Next/Link, plus Framer Motion. Data begins with `navLinks`, an array mapping labels to anchors. Hook usage follows a disciplined order: scroll listener toggles background blur, pathname updates reset the mobile menu, hash state sync ensures the highlight matches the viewport even on hash change events, while a dedicated IntersectionObserver-like routine uses `requestAnimationFrame` to compute which section sits closest to the viewport center. This method prevents thrashing compared to synchronous scroll handlers. The `handleNavClick` function intercepts anchor clicks to call `scrollIntoView`, preserving smooth transitions while still updating hashes for shareable URLs. Rendering splits between desktop plus mobile experiences, with Framer Motion providing animated indicators. Each Link wraps text plus a `motion.span` that reuses a shared `layoutId` for fluid highlight transitions.

The component relies on numerous refs: `rootRef`, `mainRef`, `sphereRef`, `viewerRef`, plus states tracking rotation, drag inertia, pointer types, plus scroll locking. `useGesture` orchestrates drag lifecycle events, while CSS variables get adjusted via ResizeObserver to adapt radius values per viewport. This labyrinthine logic underscores the methodology: complex experiences remain modular, with dedicated files managing state, event listeners, plus visual transformations without leaking responsibilities elsewhere.

Methodology extends into event hygiene. Many components remove listeners during cleanup, cancel `requestAnimationFrame` loops, plus guard for missing DOM APIs before instantiating observers. For example, `ShowcaseRow` checks `typeof ResizeObserver !== "undefined"` before instantiating to avoid SSR warnings. DomeGallery references `document.body.classList` only after confirming the root exists. These defensive moves protect future SSR builds plus reduce hydration mismatches. Contributors learn from this template, applying similar guards whenever hooking into `window`, `document`, plus `ResizeObserver`.

Routing methodology revolves around predictability. The Navbar's `navLinks` array drives both desktop plus mobile menus, guaranteeing parity between experiences. Section components expose IDs matching those hashes, preventing divergence between navigation copy plus DOM structure. When `handleNavClick` sees a hash, it prevents default navigation, calculates the target element, then calls `scrollIntoView` with smooth behavior. If the element fails to exist, the code still updates `window.location.hash` to maintain expected URL state, showing respect for user intent even under partial renders. On scroll, an evaluation function calculates which section center sits nearest the viewport center, updating `activeTarget` inside a `requestAnimationFrame` loop. This ensures the highlight transitions only when necessary, reducing layout thrashing. That method reflects a philosophy: instrumentation should guide visitors gently, not distract them with jittery UI.

Component methodology encourages client-only boundaries for interactive zones. Each file begins with "use client" when pointer events, GSAP, plus `window` access occur. This clarity aids bundling since Next.js can keep server components lean. DomeGallery, HeroSection, HeroText, Hero3D, Navbar, plus AudioPlayer all declare this directive. Conversely, server-suitable components like About versus Footer (not shown) can remain server components, keeping the hydration footprint small. This hybrid split plays into Next.js strengths, letting Bold Frame Media stream hero markup quickly while deferring heavy JavaScript until needed.
